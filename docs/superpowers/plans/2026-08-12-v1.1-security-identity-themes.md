# 航线 v1.1 安全、身份、头像与主题增强实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变现有业务契约和任何 DOM ID 的前提下，为航线全站交付稳定会话同步、双层 XSS 与全局 DFA、防绕过的腾讯云 IMS 头像上传、三套主题、统一响应式组件、安全审计和 v1.1 生产发布。

**Architecture:** 以当前 v1.0 生产源为唯一基线，新增共享会话、安全、头像、主题和壳层模块，生产页面通过适配器调用这些模块，原控制器与状态机保持原职责。所有用户写入在浏览器侧做即时预检，并在 Edge Function 侧使用同一规范化与词库产物做权威裁决；头像只能经过认证 Edge Function、真实图片校验和腾讯云 IMS 审核后由 service role 落盘。

**Tech Stack:** 无构建静态 HTML/CSS/JavaScript、Supabase JS 2.111.0、Supabase Auth/Postgres/Storage/Edge Functions（Deno/TypeScript）、腾讯云 IMS `ImageModeration` API、Node.js `node:test`、CDP/Playwright 浏览器测试、PowerShell 发布脚本。

## Global Constraints

- 不修改、重命名或删除任何现有 DOM `id`、表单 `name`、页面路由、题目、选项、计分或状态机。
- 不重写原有业务 JavaScript；只添加头像、主题、过滤和登录监听相关模块及必要接入调用。
- 不新增数据库表；唯一新增业务字段为 `public.user_public_profiles.avatar text`。
- 执行数据库 SQL 前使用已批准的第 7 任务 SQL 预览；不执行删除表、清空全表或其他毁灭性操作。
- 腾讯云 SecretId/SecretKey、Supabase service role、token、数据库密码、SMTP 凭据和 SSH 私钥不得进入代码、Git、日志或报告。
- 三套主题只改变 CSS 配色；页面布局与内容顺序保持不变。
- CSS 界面 transition/animation 固定在 180-250ms，默认 200ms 或 220ms；不得超过 300ms。
- 卡片圆角不超过 8px；不使用高饱和霓虹、纯黑遮罩或可拦截交互的装饰层。
- 根 `CHANGELOG.md` 严格按 `v0.1` 至 `v1.1` 连续排列，禁止跳号和三段版本。
- 每个任务完成后立即核对该任务的自检项；任何门禁失败时不得部署。
- 当前工作树含用户/前序会话的未提交 v1.0 改动；不得撤销、覆盖或将无关临时文件混入提交。
- 生产部署仅切换 `/var/www/MKJ`，不得修改主站根路由或 Nginx。
