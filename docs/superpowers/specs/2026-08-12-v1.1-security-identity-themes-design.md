# 航线 v1.1 安全、身份、头像与主题增强设计规格

## 1. 目标

在当前已部署的 v1.0 生产基线上新增以下能力，同时保持原求职测评、论坛、任务、商城、公告、后台、Supabase 数据流和权限模型不变：

- 修复论坛和任务页面偶发误判未登录的问题，并实时同步全站登录状态。
- 对所有用户可写的公开文本实施前端提示与后端权威校验的 XSS 双层防护。
- 使用开源词库快照构建全局 DFA 敏感词过滤，普通命中替换、高风险命中拒绝。
- 增加经腾讯云图片内容安全 IMS 审核的头像上传，并在导航、帖子和评论中显示头像。
- 增加科技浅色、科技暗色、清新蓝调三套仅改变配色的主题。
- 统一弹窗、表格、移动导航、触屏尺寸和 180-250ms 界面动效。
- 完成安全审计、分模块提交、GitHub 推送、腾讯云部署和生产冒烟报告。

本轮公开版本为 `v1.1`。项目继续保留学习演示定位，所有生产页面必须保留以下免责声明：

> 本项目仅为学习演示Demo，请勿直接线上投入正式生产使用。

## 2. 不可变约束

### 2.1 业务与 DOM 契约

- 不重写或删除任何原有业务 JavaScript 逻辑。
- 不修改、重命名或删除任何现有 DOM `id`。
- 不改变现有表单 `name`、题目、选项、计分、状态机、路由、链接目标和权限语义。
- 只新增头像、主题、输入过滤和登录监听相关代码，以及为这些新增能力所必需的 UI、测试、Edge Function、SQL、文档和部署接入。
- 新组件使用新 `data-*` 属性或新 ID，不复用现有 ID 表达不同语义。
- 当前 v1.0 未提交工作必须先独立归档，不能与 v1.1 功能提交混合。

### 2.2 数据库边界

- 不新增数据表。
- 唯一允许新增的业务字段是 `public.user_public_profiles.avatar text`。
- 头像 Storage bucket 和 RLS 属于对象存储配置，不引入业务表。
- 浏览器不得持有 `service_role` key、腾讯云 SecretId/SecretKey 或其他服务端凭据。
- 执行任何 SQL 前必须先向用户展示 SQL 预览；已批准的预览见第 6 节。
- 只有销毁数据库、清空全表等毁灭性操作需要再次暂停确认；本设计不包含此类操作。

### 2.3 视觉与动效边界

- 三套主题只覆盖 CSS 语义 token，不改变布局、内容顺序或信息架构。
- 禁止高饱和赛博朋克霓虹、纯黑弹窗遮罩和遮挡交互的装饰层。
- 卡片最大圆角为 8px；使用低透明度阴影和纤细分割线。
- 所有 CSS 界面切换、主题切换、弹窗、悬停与交互反馈时长必须在 180-250ms 内，默认使用 200ms 或 220ms。
- 现有答题自动前进视觉等待由 360ms 调整为 220ms，不改变题目顺序、答案或计分。
- `prefers-reduced-motion: reduce` 下立即切换并保持内容可见。

### 2.4 版本规则

- 新建根目录 `CHANGELOG.md`，严格按 `v0.1`、`v0.2`、...、`v0.9`、`v1.0`、`v1.1` 排列。
- 历史记录只能依据现有提交、交接文档和发布记录整理，不伪造不存在的功能。
- 禁止跳号和三段式版本号。
- 首页更新日志与 `tests/browser/changelog.test.mjs` 同步更新。

## 3. 方案选择

采用“共享增强层 + 现有页面适配器”。共享层提供会话协调、输入守卫、DFA、头像、主题和通用组件，现有控制器只在提交前、渲染后和认证边界调用这些新增接口。

未采用的方案：

- 一次性横切重写全站：修改面过大，难以证明原业务契约未改变。
- 按页面复制实现：容易形成多套认证、过滤和主题逻辑，导致新旧页面混杂。

共享层方案可以独立测试、逐模块提交和回滚，也能通过 DOM ID 快照与现有测试证明兼容性。

## 4. 会话与登录状态设计

### 4.1 共享协调器

新增 `assets/js/core/session-coordinator.js`，提供稳定接口：

- `ready(): Promise<SessionState>`：等待首次 `auth.getSession()` 完成。
- `getState(): SessionState`：读取最近一次已确认状态。
- `subscribe(listener): () => void`：订阅 `INITIAL_SESSION`、`SIGNED_IN`、`TOKEN_REFRESHED`、`SIGNED_OUT` 和恢复失败。
- `requireAuthenticatedAction(options): Promise<User>`：为受保护动作提供统一登录门禁。
- `handleApiAuthFailure(error): void`：将 Edge Function 的 `UNAUTHENTICATED` 映射为失效提示和重新登录入口。

每个论坛、任务、社区、后台、公告、商城和首页在渲染账户态前等待 `ready()`。这样消除“页面先按游客渲染、稍后才拿到已存在会话”的初始化竞态。

### 4.2 实时与跨页面同步

- 以 Supabase `onAuthStateChange` 为权威事件源。
- 同一页面收到事件后刷新导航文本、头像、权限动作和个人设置入口。
- 使用 `BroadcastChannel` 广播非敏感状态版本；不传输 access token 或 refresh token。
- 以 Supabase 自身 localStorage 事件作为跨标签页基础行为，在不支持 `BroadcastChannel` 时继续工作。
- 事件处理使用版本号取消过期异步资料查询，避免旧查询覆盖新登录状态。

### 4.3 游客与失效会话

- 游客进入论坛或任务公开列表可以看到页面；触发发帖、评论、申请、提交等受保护动作时打开共享登录弹窗，不出现空白页或原始异常。
- 登录弹窗复用首页现有认证语义和 Supabase Auth，不修改 `mkj-auth-modal`、`mkj-login-form` 等既有 ID。
- token 过期、异地下线、刷新失败或后端返回 `UNAUTHENTICATED` 时，清除陈旧登录 UI，提示“登录已失效，请重新登录”。
- 不自动无限重试，不在错误信息、日志或页面中输出 token。

## 5. 输入安全设计

### 5.1 XSS 双层防护

新增共享前端 `input-guard` 与后端等价验证器。前端只提供即时反馈，后端是最终裁决者。

检测并拒绝：

- `<script>` 及大小写、空白、实体或 Unicode 规避形式。
- `onerror`、`onclick` 等事件处理属性。
- `javascript:`、`vbscript:`、`data:text/html` 等危险 URI。
- `iframe`、`object`、`embed`、危险 `svg`/`math` 活跃内容。
- 能形成 HTML 执行上下文的编码和标签拼接载荷。

普通自然语言、数学比较符号和无执行语义的 `<`、`>` 不应误伤。命中时阻止提交，在表单附近显示可恢复的中文提示，不抛出导致页面崩溃的未处理异常。

所有用户内容继续使用 `textContent`、`createTextNode` 或结构化 DOM API 渲染。对现有静态模板 `innerHTML` 做数据流审计；只有攻击者可控内容进入 HTML sink 时才改为安全 DOM 构造。

### 5.2 全局 DFA 敏感词

- 使用兼容许可的开源中文词库固定快照，记录来源、许可证、版本和 SHA-256。
- 构建静态 trie/DFA 产物，前端与 Edge Function 使用同一份词条来源和规范化规则。
- 使用 Unicode NFKC、大小写统一和受控空白处理，阻止常见全角规避。
- 普通风险词按匹配字符数替换为等长 `*`。
- 高风险词返回 `403 CONTENT_BLOCKED`，不保存原文。
- 代码保留少量 `CUSTOM_WARN_WORDS` 和 `CUSTOM_BLOCK_WORDS` 数组；新增自定义词只能通过代码、测试和发布流程完成。

现有 `public.sensitive_words` 表、管理员页面和旧禁言兼容能力不删除、不改路由，以免改变现有业务；v1.1 的全局 DFA 不读取该表，网页后台不能管理或绕过全局规则。

### 5.3 输入覆盖矩阵

前端和后端覆盖所有真实的用户自由文本写入口：

| 模块 | 输入 |
| --- | --- |
| 论坛 | 帖子标题、帖子正文、评论 |
| 任务 | 标题、摘要、描述、申请说明、提交说明、评价、附件说明 |
| 分类 | 任务分类、任务子分类及现有可写论坛分类/标签名称 |
| 公告与商城 | 公告标题/正文、商品名称/描述等现有管理写入口 |
| 账户与反馈 | 公开昵称、留言、其他公开显示的个人自由文本 |
| 测评相关 | 资料领取、结果留言等自由文本入口 |

当前 10 道测评题的答案来自代码内固定选项，没有用户自由文本，也不向后端保存脚本文本，因此保持原契约，不制造虚假的“后端答题过滤”。如未来增加自由文本答题，必须先接入同一安全接口才能上线。

测试维护写入口清单，并要求每个写入 Edge Function 显式调用后端守卫。新增写入口未登记时契约测试失败。

## 6. 头像与 SQL 设计

### 6.1 数据模型

只在公开资料表增加一个字段：

```sql
alter table public.user_public_profiles
  add column if not exists avatar text;
```

`avatar` 保存审核通过后的公开 Storage URL。空值继续显示现有文字首字占位。导航、帖子和评论使用同一头像解析器。

### 6.2 已批准 SQL 预览

以下 SQL 已由用户确认，但设计阶段不执行：

```sql
alter table public.user_public_profiles
  add column if not exists avatar text;

insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values (
  'avatars',
  'avatars',
  true,
  2097152,
  array['image/jpeg', 'image/png', 'image/webp']
)
on conflict (id) do update
set public = excluded.public,
    file_size_limit = excluded.file_size_limit,
    allowed_mime_types = excluded.allowed_mime_types;

drop policy if exists avatars_public_read on storage.objects;
create policy avatars_public_read
on storage.objects
for select
to anon, authenticated
using (
  bucket_id = 'avatars'
  and (storage.foldername(name))[1] ~* '^[0-9a-f-]{36}$'
);

-- 故意不为 anon/authenticated 创建头像 INSERT/UPDATE/DELETE 策略。
-- 所有写入必须通过完成 JWT、文件内容和腾讯云 IMS 审核的 Edge Function。
```

### 6.3 上传安全链路

浏览器接受 JPG/JPEG、PNG、WebP，最大 2MB，并只做即时预检。认证后的 `avatar-upload` Edge Function 执行权威检查：

1. 验证 Bearer token，并从服务端会话取得 `userId`。
2. 验证请求体上限、文件扩展名、Content-Type、字节长度和文件魔数一致。
3. 解码图像，拒绝 SVG、GIF、HTML、多态文件、无效图像和超大像素图。
4. 将图像字节提交腾讯云图片内容安全 IMS；SecretId/SecretKey 只放 Supabase Secrets。
5. IMS 明确通过后才写入 `avatars/{userId}/avatar.<ext>`。
6. 可疑、违规、超时、限流、网络失败和 IMS 服务异常均 fail closed，不写入 Storage。
7. Storage 上传成功后更新 `user_public_profiles.avatar`；资料更新失败时删除刚上传的对象。
8. 更换头像成功后清理同用户旧扩展对象；失败时保留旧头像。

浏览器对头像桶只有公开读取权限，没有直接 INSERT、UPDATE 或 DELETE 策略，因此无法绕过 IMS。Edge Function 使用 service role 代办通过审核的本人写入。

## 7. 主题与界面设计

### 7.1 三套主题

主题通过 `<html data-theme>` 和 CSS 语义 token 实现，选择保存在 `localStorage`，不增加数据库字段。

| 主题 | 背景 | 表面/正文 | 主色 | 状态色 |
| --- | --- | --- | --- | --- |
| 科技浅色 | `#F4F7F8` | `#FFFFFF` / `#111820` | `#165DFF` | `#087F5B` |
| 科技暗色 | `#11151A` | `#191F26` / `#E8EDF2` | `#6E9BFF` | `#51B58F` |
| 清新蓝调 | `#F1F7FA` | `#FFFFFF` / `#17313A` | `#287FA5` | `#2E8B78` |

背景只使用低对比弱流体渐变和淡网格。装饰伪元素必须 `pointer-events: none`，处于内容层下方，并由浏览器测试验证不会覆盖按钮、链接、输入框或弹窗。

### 7.2 个人设置

新增个人设置弹窗，包含：

- 三个带色板的单选主题项，选择后即时切换并持久化。
- 当前头像、文件选择、预览、上传进度、错误提示和取消操作。
- 键盘焦点管理、Escape 关闭和恢复触发按钮焦点。

该弹窗不替换现有认证弹窗，不修改原有 ID。

### 7.3 表格、弹窗和移动端

- 任务管理表保留原数据与事件，只统一表头、筛选下拉、行悬停、浅蓝编辑按钮和红色删除按钮。
- 弹窗遮罩使用半透明灰色；暗色主题也不使用纯黑遮罩。
- 卡片圆角不超过 8px，阴影低透明，边界为 1px。
- 首页保留现有汉堡菜单；论坛、任务和后台通过共享增强在窄屏折叠导航，不改变链接层级。
- 表格在窄屏用 CSS grid 和数据标签重排，不删除字段，不让正文横向挤压。
- 触屏按钮最小尺寸为 44x44px。
- 三套主题在 375、768、1280、1920 四种视口均必须生效。

## 8. 测试与验收设计

所有行为修改遵循测试先行：先写并运行失败测试，再实现最小代码，再运行目标和全量测试。

### 8.1 契约与单元测试

- 冻结所有现有 DOM ID，测试 ID 集合不减少、不重命名。
- 冻结原题目、选项、计分、论坛操作和任务状态机契约。
- 验证 20 个生产页面加载 v1.1 共享主题、会话和必要适配器。
- 验证所有页面免责声明存在。
- 扫描 CSS transition/animation，除 reduced-motion 外均为 180-250ms。
- 会话测试覆盖初始化竞态、实时更新、过期异步取消、跨标签页、SIGNED_OUT 和后端 401。
- XSS 测试覆盖常见载荷、实体/Unicode 规避、普通文本不误伤和友好提示。
- DFA 测试覆盖最长匹配、等长星号、NFKC、高风险拒绝、自定义数组和写入口矩阵。
- 头像测试覆盖扩展名、MIME、魔数、大小、像素、解码、IMS 通过/拒绝/超时、失败不落盘、补偿删除和 RLS。
- 主题测试覆盖三套 token、localStorage、即时更新、跨页恢复和 reduced motion。

### 8.2 安全审计

完成实现后运行安全工具并进行代码数据流追踪，报告保存为 `docs/security/v1.1-security-audit.md`。检查项：

- XSS：所有攻击者可控输入到渲染 sink 和持久化路径。
- CSRF：Supabase Bearer token、CORS、状态变更方法及不可伪造性。
- RLS：私有资料、公开头像读取、头像无客户端写策略、本人边界。
- 礼包码：生成、校验、限次、奖励和权限必须由 Edge Function/RPC 完成，不能只在浏览器。
- 头像：所有绕过路径、IMS fail-closed、Secrets、格式与内容校验。
- 敏感词：全局写入口覆盖、高风险拒绝、旧后台不能控制新 DFA。

所有高危和中危发现必须修复并复审为关闭，才能进入部署。

### 8.3 生产冒烟

生产测试使用真实授权账号和真实腾讯云 IMS，不用 mock 结果冒充线上验收：

- 登录、刷新、跨页面和跨标签页状态同步。
- 游客访问论坛/任务并打开登录弹窗。
- 发帖、评论、任务申请/提交和原求职测评完整流程。
- XSS 载荷在前端和后端均被阻止，页面不崩溃。
- 普通敏感词替换、高风险敏感词拒绝。
- 合规头像上传成功并在导航、帖子、评论显示。
- 违规测试头像被真实 IMS 拒绝，并确认 Storage 中没有对应对象。
- token 失效提示重新登录。
- 20 个生产路由乘 375/768/1280/1920 四视口，无横向溢出、遮挡、控制台错误或网络错误。
- 三套主题抽样覆盖全部页面类型，并在手机端验证。
- 主站 `https://dsxnb.com/` 保持 HTTP 200，且不加载 MKJ v1.1 资源。

报告保存到 `output/playwright/v1.1-production/` 和 `docs/testing/v1.1-production-smoke.md`。

## 9. 提交、发布与回滚

### 9.1 提交顺序

1. 独立归档当前已上线的 v1.0 视觉改动，排除缓存、输出、备份和临时密钥。
2. 版本与不可变契约。
3. 会话与登录同步。
4. XSS 与全局 DFA。
5. 头像字段、RLS、Edge Function 和头像 UI。
6. 三主题、弹窗、表格和移动端。
7. 安全审计修复与报告。
8. 发布清单、交接和生产报告。

每个提交只包含对应模块，注释清晰。推送当前 `codex/` 分支，不强推或覆盖 `main`。

### 9.2 发布顺序

- 生成相互分离的 v1.1 静态包与后端包、manifest 和 SHA-256。
- 检查静态包不含 Supabase schema、函数、测试、文档、输出或凭据。
- 配置腾讯云 IMS Supabase Secrets，不记录真实值。
- 执行已批准 SQL和部署 Edge Functions，验证 RLS、角色与头像桶策略。
- 部署前为 `/var/www/MKJ` 创建时间戳 tar 和 `.previous` 回滚目录。
- 只原子切换 `/var/www/MKJ`，不修改 Nginx 或主站根路由。
- 完成线上 manifest、逐文件哈希和生产冒烟后才标记 v1.1 完成。
