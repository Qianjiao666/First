# 协作任务市场设计

日期：2026-08-15
状态：已确认，待实施计划

## 目标

将现有任务广场扩展为面向大学生的协作任务市场。学生可以通过任务获得清晰的学习方向、作品和发布者批改；具备资格的用户可以发布职业学习、项目众包和校园协作任务；多人协作任务提供受控沟通、分工、互评和最终批改闭环。

本期校园团购仅作为多人协作任务，不处理真实金额、支付、托管或退款。

## 非目标

- 不重建现有任务模块，不废弃 `task_listings`、`task_applications`、`task_reviews`、附件、活动时间线或仲裁能力。
- 不改变现有 Supabase Auth、论坛、声望基础设施、敏感词过滤、账户会话或主站根路由。
- 不引入任意用户之间的跨任务私信。
- 不在浏览器中执行特权数据库写入或权限判定。

## 信息架构

任务大厅继续使用 `/tasks/`，采用任务市场优先的 B 型布局：

- 左侧：全部任务与五类任务筛选。
- 主区域：支持职业方向、难度、人数、截止日期、是否多人协作、是否有批改的紧凑任务卡片列表。
- 顶部：发布资格状态和创建任务命令。
- 任务卡片：任务类型、职业方向、难度、报名/接取人数、截止时间、发布者身份、批改标记和按当前用户状态显示的行动按钮。

任务类型由管理员维护，第一期预置：

1. 职业学习与作品集
2. 技术开发与数据任务
3. 设计、内容与运营协作
4. 校园协作与团购组织
5. 社团或公益项目

## 角色与资格

### 用户角色

- 学生：浏览、申请、参与、提交、互评。
- 发布者：创建、发布、接取成员、分工、批改和确认完成。
- 管理员：维护分类、模板、资格规则，处理冻结与仲裁。

同一用户在不同任务中可以拥有不同的协作身份。一个任务内可同时存在发布者、申请者、已接取成员、批改者和管理员仲裁人员。

### 发布资格

发布资格使用声望自动解锁与管理员例外管理的组合：

- 配置每种任务类型的最低声望门槛。
- 用户声望达到门槛后自动获得相应类型的发布资格。
- 管理员可提前授予、限制任务类型、临时冻结或撤销发布资格。
- 创建草稿、保存草稿和发布都必须由 Edge Function 与 service-only RPC 重复校验资格；前端状态仅作引导，不能作为安全控制。

## 模板与任务数据

管理员按任务类型维护模板。模板包含：

- 标题、概要、详细说明与截止时间等系统必填字段。
- 推荐职业方向、技能标签、难度、默认人数和是否多人协作。
- 申请说明、分工、提交材料和完成检查项。
- 发布者批改维度与默认互评维度。

发布者从模板新建任务，可填写业务内容和可选字段，但不得删除模板定义的必填字段、提交要求或批改检查项。任务创建时保存模板版本快照，模板后来变更不影响已发布任务。

现有 `task_listings` 继续代表任务；现有 `task_applications` 继续代表每位成员的申请和接取状态；现有 `task_reviews` 继续保存最终评价。新增的协作元数据必须通过引用现有任务和申请记录关联。

## 状态与协作流程

1. 发布者选择已获授权的任务类型和模板，填写并保存草稿或发布。现有 draft/published/closed/archived 生命周期不变。
2. 学生筛选市场任务并提交申请说明。
3. 成功申请后，系统创建申请咨询会话，仅申请者和发布者可见。
4. 发布者接取申请后，该会话升级为正式协作会话。多人任务把所有已接取成员与发布者加入同一任务会话。
5. 发布者可以给已接取成员记录分工；成员可查看全体分工和个人提交状态。
6. 成员提交成果、附件和自证说明。多人任务进入互评窗口，成员只能评价同一任务中其他已接取成员。
7. 发布者按任务模板的完成检查项批改，可要求补充、确认完成或发起争议。只有最终确认完成才触发现有的幂等声望奖励。
8. 争议继续使用现有仲裁与活动时间线。任务关闭、申请取消或仲裁结束后，相关会话转为只读。

互评用于记录协作贡献，不能单独修改任务完成状态、声望或发布资格。互评原始内容仅对受评者、发布者和必要的管理员仲裁人员可见；其他成员只看到聚合后的协作状态。

## 协商会话

会话仅存在于任务关系中，不提供用户搜索或跨任务私信。

- 申请咨询会话：一名申请者与发布者之间，创建于申请成功时。
- 正式协作会话：发布者与所有已接取成员共享，创建或升级于首位成员被接取时。
- 管理员访问：仅仲裁、敏感词处置或合规审计，并记录访问原因和审计事件。
- 所有消息经现有敏感词过滤和 XSS 防护；禁言用户不能发送消息、申请或提交。
- 消息发送、读取、成员加入与只读转换均由 Edge Function 验证任务参与关系和生命周期状态。

## 页面与后台

### 任务大厅 `/tasks/`

实现市场优先布局，提供类型、职业方向、难度、人数、日期和批改标签筛选。任务卡使用身份感知操作，未获发布资格的用户不会获得可绕过的创建动作。

### 发布页 `/tasks/create/`

先选择任务类型和模板，再显示模板字段、协作人数和批改要求。无资格用户可查看明确的声望解锁条件和管理员限制说明。

### 任务详情 `/tasks/detail/`

保留现有活动时间线、附件、申请和提交区域，增加：

- 申请咨询。
- 正式协作会话、成员列表和分工。
- 互评状态与发布者批改检查项。

页面只渲染当前用户有权读取和操作的区域。

### 我的任务 `/tasks/my/`

区分我发布的、我申请的、我参与协作的和待我批改的任务。优先展示未读协商、补充请求、待互评、待批改和临近截止时间。

### 任务后台 `/admin/tasks/`

管理员可管理任务类型、模板、声望门槛、例外授权与冻结；可查看与仲裁关联的会话和审计事件。后台不得允许管理员伪装成普通参与者发送协商消息。

## 数据、权限与安全

新增实体：任务模板、任务模板快照、任务类型资格规则、用户发布资格例外、任务成员分工、协商会话、会话成员、消息、成员互评和审计事件。

所有表启用 RLS。浏览器仅通过新建或扩展的 Edge Function 写入：

1. 由服务端恢复经过验证的认证用户。
2. 检查全局能力、发布资格、禁言状态和任务参与关系。
3. 对文本执行敏感词过滤、长度限制和 XSS 防护。
4. 调用仅向 `service_role` 授权的 `SECURITY DEFINER` RPC。
5. 写入稳定的活动记录和必要审计事件。

匿名用户只能读取已发布任务的公开摘要；不得读取申请、协作成员详情、会话、提交材料、互评或审计记录。管理员权限同样通过服务端能力校验，且对会话的例外读取必须留下审计记录。

## 错误处理

- 权限、资格、禁言和生命周期冲突采用现有安全错误 envelope，前端显示可操作的中文提示，不泄露数据库细节。
- 敏感词命中在草稿和非公开阶段按既有策略返回 warning；发布、消息、批改及提交按现有策略阻断或要求修改。
- 已关闭、已取消或仲裁结束的会话拒绝新的消息并显示只读原因。
- 重复申请、重复接取、重复完成、重复奖励和重复互评全部通过唯一约束或幂等键处理。

## 验收

- 任务类型、模板和发布资格的数据库/RPC/Edge Function 单元测试。
- 权限矩阵测试：学生、声望解锁发布者、管理员例外授权者、被冻结者、禁言者和管理员。
- 会话参与者、RLS、管理员审计、XSS、敏感词与附件访问回归测试。
- 多人协作申请、接取、分工、消息、提交、互评、批改、补充、完成和仲裁的集成测试。
- 375、768、1280、1920 宽度的浏览器验收，无横向溢出、键盘可用、控制台错误或越权内容。
- 部署前执行 Supabase migration、Edge Function 部署、真实角色矩阵、生产静态包与回滚演练；只更新 `/var/www/MKJ`，不修改主站路由或 Nginx。
