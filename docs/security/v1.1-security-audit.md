## 已关闭发现

### SEC-001 Edge 认证失败处理被局部变量遮蔽

- 严重性：Medium
- 置信度：High
- 状态：Closed
- 位置：`assets/js/core/runtime.js:74`、`assets/js/core/runtime.js:92`
- 问题：`invokeFunction()` 原先把 Supabase session 保存到名为 `session` 的局部变量。Edge Function 返回 `UNAUTHENTICATED` 后，错误分支对该对象调用 `handleApiAuthFailure()`，导致二次 `TypeError`，全局会话协调器无法进入 expired 状态，也无法稳定提示重新登录。
- 影响：token 过期或异地下线时，论坛、任务等跨页面操作可能停留在错误状态，用户收不到预期重登提示。此问题不绕过认证，但破坏认证失效处置。
- 修复：局部变量改为 `activeSession`，Authorization 仍使用其 access token；认证失败统一交给共享 `session` 协调器。
- 回归：`tests/browser/runtime-auth-failure.test.mjs` 与 `tests/security/v1.1-static-audit.test.mjs` 锁定该分支。

## XSS

- 前端输入：发帖、评论、任务标题/摘要/正文、申请/提交/评价、分类名称/说明、公告和管理员礼包标题均通过 `guardFormData()`。固定选项测评没有自由文本入口。
- 后端二次校验：`tests/functions/content-coverage.test.mjs` 枚举 18 个后端公共文本面，每个写入点在第一次 RPC/insert 前调用 `guardPublicText()`；WARN 词替换为 `*`，BLOCK 与脚本载荷拒绝落库。
- 输出编码：论坛、任务和公共身份使用 `textContent`/DOM 节点。公告是唯一接收数据库文本的 `innerHTML` 路径；`announcements/announcements.js:106` 先转义 HTML，Markdown 链接只接受 `http/https`，之后才在 `:193`、`:244` 写入受控标记。
- 首页其余 `innerHTML` 数据仅来自代码内固定题目、维度、评价和 FAQ 常量，未发现用户输入到 HTML sink 的路径。
- 结论：未发现高置信度存储型或 DOM XSS。

## CSRF、CORS 与 Bearer

- 所有状态变更 Edge Function 从 `Authorization: Bearer` 取 token，并通过 `auth.getUser()` 得到可信用户 ID；未使用浏览器 Cookie 作为认证来源。
- `supabase/functions/_shared/http.ts:13` 返回 `Access-Control-Allow-Origin: *`，但没有 `Access-Control-Allow-Credentials`。攻击站点无法读取受害者 origin 的 localStorage token，也不能让浏览器自动附带 Bearer token，因此当前配置不形成可利用 CSRF。
- OPTIONS 仅返回预检响应，没有状态变更；未发现 GET 状态变更。
- 结论：wildcard CORS 保留为非凭据化 Supabase Function 的互操作配置。部署后仍须以生产响应头复核；若未来改用 Cookie 或允许 credentials，必须改为显式来源 allowlist。

## RLS 与授权

- 头像迁移只新增 `user_public_profiles.avatar text`，未新建业务表或其他字段。
- `avatars` 仅有 public SELECT policy；没有 anon/authenticated INSERT、UPDATE、DELETE policy。浏览器不能直写头像桶，认证 Edge Function 使用 service role 写入。
- 状态变更 `SECURITY DEFINER` RPC 均设置空 `search_path`，并撤销 `public/anon/authenticated` 的默认执行权限，只授予 `service_role`；Edge Function 在调用前用 JWT 用户和服务端权限检查建立 actor。
- 有意公开的 `get_user_reputation_summary(uuid)` 只返回公开声望/评价聚合；`recommend_task_listings(uuid, integer)` 在函数内部要求 `auth.uid() = p_user_id`；`get_user_capabilities()` 使用 `security invoker` 并绑定 `auth.uid()`。
- `can_access_task_storage(uuid, uuid)` 是供 RLS 使用的只读布尔 helper。实际 RLS 策略传入 JWT claim；公开 RPC 本身只泄露“某用户是否可访问某任务”的布尔关系，不返回对象或附件内容。该元数据面保留在远端权限验证清单，不作为已确认 High/Medium 漏洞。
- 结论：本地 SQL 合同未发现可利用的 RLS 绕过。远端数据库尚未部署 v1.1 migration，必须在上线门禁中用真实 anon/authenticated/service-role 身份验证。

## 礼包码

- 浏览器 `assets/js/core/redeem.js` 只规范化输入并调用 `redeem` Edge Function，不在前端生成奖励或修改积分。
- Edge Function 经 `requireContext()` 得到 JWT 用户 ID，再调用 `public.redeem_code`。
- RPC 使用 `FOR UPDATE` 行锁，检查启用状态、有效期、最大次数与唯一 user/code usage；奖励写入在数据库事务内完成。
- 管理端禁止礼包码授予 `ADMIN` 角色或 `admin:*` 权限。
- `redeem_code(uuid, text)` 明确撤销 `public/anon/authenticated`，仅授予 `service_role`。
- 结论：礼包码创建、核销、幂等与奖励授权均由服务端权威执行。

## 头像安全与 IMS

- Edge Function 在任何 Storage upload 前依次执行：JWT 身份校验、严格 Base64 解码、2MB 限制、扩展名/MIME/魔数/图片结构/尺寸/像素校验、腾讯云 IMS。
- `supabase/functions/_shared/tencent-ims.ts:112` 只接受精确 `Suggestion === "Pass"` 且存在 RequestId。Review、Block、腾讯 API Error、非 2xx、网络错误、超时、缺少密钥全部 fail closed。
- 对象路径固定为 `{JWT userId}/avatar.{jpg|png|webp}`；客户端不能指定目录。
- Storage 成功而资料更新失败时，函数删除新对象并尽力恢复旧字节；违规或不确定图片在首次写入前即被拒绝。
- 腾讯凭据只从 `Deno.env`/Supabase Secrets 读取，不进入浏览器或仓库。
- 结论：本地代码与 mock 测试满足“后端审核、失败关闭、违规图片绝不入桶”。真实 IMS Pass/Block 仍必须在部署后验证，mock 不等同线上验收。

## DFA 全局覆盖

- 前后端使用固定开源 DFA 词库与代码内少量冻结自定义数组，没有新增网页词库管理能力。
- 公共文本面覆盖论坛、任务、任务评价、附件说明、分类、公告、商城名称/说明与礼包标题，不限于论坛。
- WARN 命中替换 `*`，BLOCK 直接拒绝；后端在持久化前重复执行，不能仅靠禁用前端绕过。
- 旧的敏感词后台属于既有管理面，但 v1.1 固定 DFA lexicon 不从该表加载，因此不能通过网页修改本版本词库。

## 凭据与供应边界

- 扫描 225 个 Git 跟踪文件，排除 vendor、deployment、output 和测试夹具；未发现私钥、Tencent/AWS Secret ID 形态、带凭据数据库 URL 或硬编码 service-role/密码/token。
- 最近 21 个提交的内容扫描未发现上述凭据形态；Git 历史没有跟踪 `.env*`。
- 工作树不存在 `.env*`。`supabase-config.js` 的 publishable key 是预期公开配置，不作为秘密误报。
- 根目录临时 `.pub` 仅为公钥且未跟踪；未发现对应私钥。
- 测试中的 `unit-test-secret-*` 是确定性假值，不用于部署，也未进入发布包。
